# bank-account

Java 17 Spring Boot service for opening and managing bank accounts. Account numbers are generated by the server. Balances are stored as decimal values with two fraction digits. Data is kept in an in-memory H2 database and disappears when the process stops.

## Run with Docker

```bash
docker compose up --build
```

The service listens on [http://localhost:8080](http://localhost:8080). Check [http://localhost:8080/actuator/health](http://localhost:8080/actuator/health) until it reports `UP`.

Stop it with `docker compose down`.

## Tests

With Java 17 installed:

```bash
./mvnw test
```

Without a local JDK, run the same Maven wrapper in the Java 17 image used by the Dockerfile:

```bash
docker run --rm \
  -v "$PWD":/src \
  -v bank-account-m2:/root/.m2 \
  -w /src \
  docker.m.daocloud.io/library/eclipse-temurin:17-jdk \
  ./mvnw -B test
```

## Account

| Field | Rules |
|---|---|
| `accountNumber` | 16 digits, generated on create, primary key |
| `holderName` | 1–100 characters |
| `holderId` | 18-digit ID card number, pattern `^[1-9]\d{16}[\dXx]$` |
| `contactInfo` | 1–200 characters |
| `balance` | `0.00` or greater, at most two decimal places |
| `status` | `OPEN` on create, `CLOSED` after delete |

One holder ID can own more than one account. Delete is a soft delete: the row stays, and `status` becomes `CLOSED`.

## API

Error responses use this shape:

```json
{
  "error": "account_not_found",
  "message": "Account number 1000000000000001 does not exist",
  "fields": {}
}
```

Validation failures put the field messages in `fields`.

### Create an account

`POST /accounts`

Header `Idempotency-Key` is required. The key is 1–64 characters and may contain letters, digits, `_`, and `-`. The same key and the same body return the original `201` response for 24 hours and do not open a second account. The same key with a different body returns `409`.

```bash
curl -i -X POST http://localhost:8080/accounts \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: manual-001" \
  -d '{"holderName":"Ada Lovelace","holderId":"110101199001011234","contactInfo":"ada@example.com","balance":1250.50}'
```

`201 Created` includes a `Location` header. The body is the new account, including the generated `accountNumber` and `status` `OPEN`.

### Get one account

`GET /accounts/{accountNumber}`

Returns the account, including a closed one. A missing account returns `404`.

Successful reads are cached by account number. Updating, closing, or transferring that account removes the cached details after the change is committed.

### List accounts

`GET /accounts?page=0&size=20`

`page` starts at 0. `size` defaults to 20 and must be from 1 to 100. Results are ordered by account number and include closed accounts.

```json
{
  "accounts": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0
}
```

### Update an account

`PATCH /accounts/{accountNumber}`

Send `holderName`, `contactInfo`, or both. Omitted fields stay unchanged. A closed account cannot be updated.

```bash
curl -i -X PATCH http://localhost:8080/accounts/9269246196529632 \
  -H "Content-Type: application/json" \
  -d '{"contactInfo":"king@example.com"}'
```

### Delete an account

`DELETE /accounts/{accountNumber}`

Returns `204` and sets `status` to `CLOSED`. Deleting a closed account returns `409`. The row is not removed.

### Transfer funds

`POST /accounts/transfers`

Moves money from one open account to another in a single transaction and stores a transfer record. The two account rows are locked in account-number order so concurrent transfers cannot overdraw a balance.

```bash
curl -i -X POST http://localhost:8080/accounts/transfers \
  -H "Content-Type: application/json" \
  -d '{"fromAccountNumber":"9269246196529632","toAccountNumber":"5435349622053226","amount":4.50}'
```

`200` returns the transfer `id`, both accounts after the balance change, the `amount`, and `createdAt`. A rejected transfer does not change either balance and does not write a transfer row.

## Errors

| Situation | Status | `error` |
|---|---|---|
| Missing or invalid create fields | 400 | `validation_failed` |
| Missing `Idempotency-Key` | 400 | `missing_idempotency_key` |
| Malformed `Idempotency-Key` | 400 | `invalid_idempotency_key` |
| Same idempotency key, different body | 409 | `idempotency_conflict` |
| Same idempotency key still processing | 409 | `idempotency_in_progress` |
| Account does not exist | 404 | `account_not_found` |
| Update or transfer on a closed account, or deleting it again | 409 | `account_closed` |
| Update body has neither `holderName` nor `contactInfo` | 400 | `EMPTY_UPDATE_REQUEST` |
| Holder name blank or longer than 100 characters | 400 | `INVALID_ACCOUNT_HOLDER_NAME` |
| Contact info blank or longer than 200 characters | 400 | `INVALID_CONTACT_INFO` |
| `page` below 0, or `size` outside 1–100 | 400 | `validation_failed` |
| Transfer amount below `0.01` or more than two decimal places | 400 | `validation_failed` |
| Transfer to the same account | 400 | `same_account` |
| Source balance is too low | 409 | `insufficient_funds` |
